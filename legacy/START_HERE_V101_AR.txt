تنبيه v102: تعليمات الخصوصية في هذا الدليل قديمة؛ اتبع START_HERE_V102_AR.txt لإعداد بيانات الشركة من المدير.

بصائر الخليج — Flower Light — v101

ما تم إصلاحه:
1. إصلاح أسماء دالة نسخ المنتج الأربعة، وفتح نموذج تعديل النسخة بعد نجاح النسخ.
2. إصلاح توقف لوحة الإدارة: تعريف MAX_PRODUCT_IMAGES قبل نشر FL_ADMIN_CORE.
3. بناء حقيقي باستخدام esbuild: المخرجات داخل dist فقط. ملفات المصدر باقية للتعديل.
4. إصدار الكاش وروابط الأصول v101 لتحديث الملفات عند عودة الزائر.
5. اختبار نسخ المنتج في Chromium واختبار تنظيفه عند فشل حفظ المعرض في VM.
6. زر «تحسين الصور القديمة» في لوحة المدير. ينشئ صور WebP كبيرة وصغيرة،
   ويستبدل مراجعها بمعاملة SQL واحدة لكل مسار، دون حذف الصور الأصلية.
   يتوقف عند أول خطأ ويحمّل تقرير JSON للمراجعة. إذا انقطع الاتصال بعد الرفع
   قد تبقى ملفات جديدة غير مرتبطة؛ لا تحذفها قبل التأكد من مسارات قاعدة البيانات.
7. توليد canonical وsitemap وrobots وروابط المشاركة من رابط Pages أثناء البناء.
8. تجهيز إعدادات سياسة الخصوصية في site-settings.json. لا تزال بحاجة لبيانات المالك.

خطوات التحديث بالترتيب:
1. احتفظ بنسخة احتياطية من المستودع وقاعدة البيانات وملفات Storage.
2. في Supabase > SQL Editor > New query:
   افتح UPGRADE_EXISTING_V101.sql من هذه الحزمة، وانسخ محتواه وشغله.
   يجمع: حد طلبات العملاء، زر تثبيت التطبيق، أعمدة الأسعار، ودالة تحسين الصور.
   هو مخصص لقاعدة موجودة. لا تشغّل SUPABASE_SETUP.sql على القاعدة الحالية.
   هذا الملف لم يُنفذ على قاعدة بياناتك في هذه الجلسة.
3. افتح site-settings.json:
   siteUrl: الرابط الصحيح الذي يظهر في GitHub > Settings > Pages.
   privacy.legalName: الاسم القانوني الكامل.
   privacy.commercialRegistration: رقم السجل التجاري.
   privacy.contact: وسيلة التواصل المخصصة لطلبات الخصوصية.
   privacy.retention: مدة الاحتفاظ الفعلية المعتمدة لديك.
   privacy.additionalServices: تفاصيل الخدمات الإضافية إن وجدت.
   الحقول الفارغة تبقي الصفحة مسودة وتمنع فهرستها. تعبئتها تولد صفحة من النص
   الموجود دون علامة المسودة؛ ذلك ليس مراجعة قانونية أو إثباتاً لامتثال السياسة.
   البناء لا يحذف بيانات العملاء تلقائياً عند انقضاء المدة؛ يجب تنفيذ سياسة الاحتفاظ عملياً.
4. ارفع محتويات هذه الحزمة إلى جذر مستودع المشروع، بما فيها .github/workflows
   وscripts وtests وpackage-lock.json. لا ترفع ZIP نفسه على أنه الموقع.
   لا حاجة لرفع dist عند استخدام GitHub Actions؛ سيعاد بناؤه.
5. GitHub > Settings > Pages > Build and deployment > Source > GitHub Actions.
   يوجد workflow جاهز باسم Build, test and deploy Pages. يعالج main أو master
   وينشر من الفرع الافتراضي فقط بعد نجاح البناء والاختبارات. لاسم فرع مختلف،
   عدّل branches في .github/workflows/pages.yml.
   لا تُبقِ workflow نشر قديم يرفع جذر المستودع بالتوازي مع هذا workflow.
6. افتح Actions وتأكد من نجاح Build, test and deploy Pages.
   يستخدم البناء رابط Pages الذي يوفره GitHub تلقائياً، بما في ذلك النطاق المخصص.
   لا تعني الاختبارات المحلية أن نشر GitHub تم أو أن الاختبارات هناك نجحت.
7. افتح الموقع ثم ?admin=1، وسجّل الدخول. اختبر على منتج تجريبي:
   إضافة صورة، نسخ المنتج، مراجعة الأسعار والمواصفات، ثم حذف النسخة.
   اختبر استيراد Excel بمنتج واحد قبل الاستيراد الكبير.
8. في لوحة المدير > المنتجات والكتالوجات > تحسين الصور القديمة:
   يظهر عدد المسارات القديمة في رسالة التأكيد. يبدأ بعد موافقتك داخل اللوحة.
   اترك الصفحة مفتوحة واحفظ تقرير المسارات الذي يتم تنزيله.
   الأداة تعالج المنتجات المحملة في لوحة الإدارة، ولا تشمل الشعار أو الباركود أو PDF.
   لم تُرحّل صور قاعدة بياناتك الحقيقية في هذه الجلسة.
9. إن بقيت صفحة قديمة، استخدم Ctrl+Shift+R مرة واحدة ثم أغلق التبويب وأعد فتحه.

للتشغيل محلياً (Node 22 أو أحدث):
  npm ci
  npm run test:static
  npm run build
  npx playwright install chromium
  npm run test:browser
اختبار النسخة المصغرة في Linux/macOS:
  FL_TEST_DIST=1 npm run test:browser
وفي PowerShell:
  $env:FL_TEST_DIST='1'; npm run test:browser

نشر يدوي بديل:
المجلد dist يحتوي ملفات النشر المصغرة فقط. إذا كنت ستستخدم Deploy from a branch،
انشر محتوياته بعد ضبط site-settings.json وإعادة البناء. لا تنشر ملفات المصدر
وتتوقع التصغير تلقائياً. المجلد dist المرفق يحمل الرابط الافتراضي غير المؤكد.
