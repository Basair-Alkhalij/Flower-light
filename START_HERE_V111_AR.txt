FLOWER LIGHT / BASAIR GULF — v111B (1.1.1)

هذه النسخة تبني فوق v111A المستقرة وتنفذ المهمة 3 فقط: صفحات ثابتة للمنتجات والأقسام لتحسين SEO ومعاينات واتساب/تيليجرام.

ما تم:
- روابط مشاركة المنتج: /p/<id>/
- روابط مشاركة القسم: /c/<slug>/
- يبقى ?product= و?category= مدعومين للروابط القديمة ولتحويل الصفحات الثابتة إلى الواجهة التفاعلية.
- build يجلب categories/products/product_images الظاهرة من Supabase عبر REST بالمفتاح العام الموجود في config.js.
- build يولد title/description/canonical/og/twitter وProduct JSON-LD للمنتجات.
- build يولد sitemap.xml من البيانات الحالية.
- المنتج المخفي أو المنتج الموجود داخل قسم مخفي لا يحصل على صفحة مشاركة.
- Service Worker لا يعترض /p/ و/c/.
- GitHub Actions يعيد البناء كل 6 ساعات ويمكن تشغيله يدويًا.

لا توجد ترقية SQL جديدة. لا تشغّل SUPABASE_SETUP.sql.

فحوصات قبل النشر على Windows PowerShell:
1) npm.cmd ci --no-audit --no-fund
2) npm.cmd run build:check
3) npm.cmd run test:static
4) npm.cmd run build
5) npx.cmd playwright install chromium
6) $env:FL_TEST_DIST="1"
7) npm.cmd run test:browser

مهم: build الإنتاجي يجب أن يملك اتصالًا بـSupabase؛ إذا فشل جلب البيانات يجب أن يفشل build ولا يتم النشر. FL_SKIP_STATIC_PAGES=1 مخصص للاختبارات المحلية فقط وليس للنشر.

بعد النشر:
- افتح رابط منتج من /p/<id>/ وتأكد من أن واتساب يعرض اسم المنتج وصورته.
- افتح /sitemap.xml وتأكد من وجود /p/ و/c/.
- في Google Search Console افحص canonical وبيانات الصفحة.
