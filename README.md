# بصائر الخليج — Flower Light v111G

موقع GitHub Pages ثابت لإدارة وعرض منتجات Flower Light، مع Supabase للمصادقة والبيانات والتخزين وEdge Functions.

**الإصدار الحالي:** v111G (`package.json` = `1.1.1`).


## ما الجديد في v111G — ترتيب الكمية في رسالة واتساب

- تبقى ميزة **كتابة الكمية مباشرة** من v111F كما هي، مع زري **+** و**−**.
- سطر كل منتج في رسالة واتساب أصبح ثابتًا: **اسم المنتج/الكود أولًا ثم `*` ثم الكمية**.
- أضيف تثبيت لاتجاه السطر حتى لا تعكس واتساب أو العربية موضع الكمية عند خلط النص العربي مع الأكواد والأرقام.
- إذا كان اسم المنتج والكود متطابقين (مثل `1230`) لا يتكرر النص، ويظهر مثل: `1230 * 2`.
- لا توجد أي migration أو تغييرات في قاعدة البيانات.


## ما الجديد في v111F — إدخال الكمية مباشرة

- يمكن للزائر الضغط على رقم الكمية داخل بطاقة المنتج وكتابة العدد المطلوب مباشرة، مع بقاء زري **+** و**−**.
- نفس الإدخال المباشر متاح داخل نافذة **قائمة الطلب**.
- الحقل رقمي بحد أدنى 1 وحد أقصى 9999، وتُصحح القيم خارج النطاق تلقائيًا.
- عند الضغط على الحقل يتم تحديد الرقم لتسهيل استبداله بسرعة.
- لا توجد أي migration أو تغييرات في قاعدة البيانات.


## ما الجديد في v111E — ترتيب أزرار المنتج

- عند تفعيل قائمة طلب عرض السعر تصبح أزرار بطاقة المنتج شبكة متناسقة 2×2: **تحميل + مشاركة** في الصف الأول، و**واتساب + طلب عرض السعر** في الصف الثاني.
- زر واتساب وزر طلب عرض السعر لهما عرض وارتفاع متقاربان في الصف الثاني.
- عند إخفاء طلب عرض السعر من لوحة المدير يعود التخطيط تلقائيًا إلى الشكل السابق: **تحميل + مشاركة** في الأعلى و**واتساب بعرض كامل** في الأسفل.
- لا توجد أي migration أو تغيير قاعدة بيانات إضافي في v111E.


## ما الجديد في v111D — تحكم المدير بظهور طلب عرض السعر

- أضيف إعداد للمالك داخل لوحة المدير باسم **إظهار قائمة طلب عرض السعر للزوار**.
- عند إيقافه تختفي أزرار «أضف لقائمة الطلب» والشريط العائم ونافذة الطلب من الموقع العام، ولا يمكن الإضافة أو الإرسال عبر واجهة القائمة.
- عند إعادة تشغيله تعود الميزة، وتبقى القوائم المحلية المحفوظة على أجهزة الزوار محفوظة.
- الإعداد مخزن في `site_settings.quote_list_enabled` وقيمته الافتراضية `true` حفاظًا على سلوك v111C.
- أضيفت migration مستقلة وملف `supabase/UPGRADE_EXISTING_V111.sql` للترقية الآمنة من النسخة الحالية.


## ما الجديد في v111C — المهمة 4: قائمة طلب عرض السعر

- يمكن للزائر إضافة عدة منتجات إلى قائمة واحدة وتحديد كمية كل منتج.
- القائمة تحفظ محليًا في المتصفح بالمفتاح `fl_quote_list_v1` ولا تنشئ سجلات جديدة في قاعدة البيانات.
- الحد الأقصى 30 صنفًا، والكمية لكل صنف من 1 إلى 9999.
- يظهر شريط عائم «قائمة الطلب (N)» عند وجود أصناف، وتفتح نافذة يمكن منها تعديل الكميات والحذف وإضافة اسم وملاحظات اختيارية.
- الإرسال يجمع الأصناف في رسالة واتساب واحدة مرتبة، ويمنع الإرسال إذا تجاوز الرابط الحد الآمن التقريبي 1800 حرف.
- أحداث التحليلات الخاصة بالقائمة ترسل عدد الأصناف فقط دون الاسم أو الملاحظات أو أي بيانات شخصية.
- جدول `quote_requests` التاريخي لم يُحذف لأن عدد صفوفه في قاعدة الإنتاج لم يُتحقق منه ضمن هذه المهمة؛ لا توجد migration مدمرة في v111C.


## ما الجديد في v111B — المهمة 3: صفحات SEO ومشاركة ثابتة

- البناء يولّد صفحة HTML ثابتة لكل منتج ظاهر في `dist/p/<id>/index.html` ولكل قسم ظاهر في `dist/c/<slug>/index.html`.
- الصفحات الثابتة تحتوي `title` و`description` و`canonical` وOpen Graph وTwitter Card، وللمنتج JSON-LD من نوع `Product`.
- صورة المشاركة للمنتج تؤخذ من صورة المنتج العامة في bucket `product-images`، مع fallback إلى `share-image.jpg` إذا لم توجد صورة صالحة.
- يتم توليد `dist/sitemap.xml` تلقائيًا من المنتجات والأقسام الظاهرة فقط، مع `lastmod` من `updated_at` متى توفر.
- روابط المشاركة من الواجهة أصبحت `/p/<id>/` و`/c/<slug>/` بدل روابط query، بينما يبقى `?product=` و`?category=` مدعومًا للروابط القديمة ولتحويل الزائر من الصفحة الثابتة إلى الكتالوج التفاعلي.
- Service Worker لا يعترض مسارات `/p/` و`/c/` حتى لا يقدم نسخة HTML قديمة.
- GitHub Pages يعيد البناء تلقائيًا كل 6 ساعات، إضافة إلى push و`workflow_dispatch`.
- إذا تعذر جلب بيانات Supabase أثناء بناء الإنتاج يفشل build بوضوح بدل نشر موقع يحذف صفحات المشاركة. للاختبار المحلي فقط يمكن استخدام `FL_SKIP_STATIC_PAGES=1`.
- أضيف `tests/static-pages.mjs` للتحقق من canonical وOG والصور والهروب من HTML واستبعاد المنتجات المخفية والسitemap وفشل الجلب.
- لا توجد تغييرات قاعدة بيانات في v111B.

## ما الجديد في v110

- تقسيم `app.js`: نقل GA4 إلى `analytics.js` ونقل عارض كتالوج PDF الكسول إلى `catalog-pdf-viewer.js`.
- تقسيم `admin.js`: نقل مصمم الداتا شيت إلى `admin-datasheet.js` باستخدام `FL_ADMIN_CORE` مثل بقية وحدات المدير.
- تقسيم `style.css` إلى وحدات داخل `styles/` مع إبقاء `style.css` كنقطة دخول واحدة؛ عملية build تجمعها إلى ملف CSS واحد داخل `dist`.
- إنتاج نسخة Supabase ذاتية الاستضافة: أثناء `npm run build` يتم تنزيل الإصدار المثبت `@supabase/supabase-js@2.57.4` مرة واحدة إلى `dist/supabase-vendor.js`، ويُعاد ربط `index.html` به. لذلك الموقع المنشور لا يعتمد على CDN لـSupabase وقت التشغيل.
- توحيد ترقية قاعدة البيانات بعد v105 في ملف واحد: `supabase/UPGRADE_EXISTING_V110.sql`.
- ملفات الترقية المتكررة القديمة v106/v108 نُقلت إلى `legacy/sql/`، بينما بقيت migrations الأصلية داخل `supabase/migrations/` كسجل تاريخي واضح.
- تحديث ميزانيات أحجام الملفات وفحوصات GitHub Actions لتشمل الوحدات الجديدة.

## النشر على GitHub Pages

استخدم **GitHub Actions فقط**:

`Settings → Pages → Build and deployment → Source → GitHub Actions`

Source = GitHub Actions

لا تستخدم **Deploy from a branch**، ولا ترفع `dist` أو `node_modules` يدويًا. Workflow `pages.yml` يقوم بـ:

1. `npm ci`
2. `npm run test:static`
3. `npm run build`
4. تثبيت Chromium
5. `npm run test:browser` على `dist`
6. نشر `dist` إلى GitHub Pages

## الترقية من قاعدة موجودة

### إذا كانت القاعدة على v105 أو أحدث

إذا كانت قاعدة البيانات لديك مطبقة عليها v110 مسبقًا، شغّل الآن فقط:

`supabase/UPGRADE_EXISTING_V111.sql`

والنتيجة النهائية المتوقعة:

`UPGRADE_EXISTING_V111_OK`

أما إذا كانت قاعدة موجودة على v105 ولم تُطبّق عليها v110 بعد، شغّل أولًا `supabase/UPGRADE_EXISTING_V110.sql` ثم `supabase/UPGRADE_EXISTING_V111.sql`. لا تشغّل `SUPABASE_SETUP.sql` مرة أخرى على قاعدة حية موجودة.

### إذا كانت القاعدة أقدم من v105

طبّق أولًا `supabase/UPGRADE_EXISTING_V105.sql`، ثم `supabase/UPGRADE_EXISTING_V110.sql`، ثم `supabase/UPGRADE_EXISTING_V111.sql`.

## Supabase Auth

في إعداد الإنتاج الحالي تم تأكيد ما يلي أثناء الإعداد اليدوي:

- التسجيل العام **Sign-ups = OFF**.
- MFA/TOTP مفعّل لحساب مالك Supabase.

هذه إعدادات حساب/مشروع في Supabase وليست ملفات داخل المستودع؛ افحصها يدويًا إذا نُقل المشروع إلى حساب أو مشروع Supabase جديد.

## بناء واختبار محلي

على Windows PowerShell:

```powershell
npm.cmd ci
npm.cmd run build:check
npm.cmd run test:static
npm.cmd run build
npx.cmd playwright install chromium
$env:FL_TEST_DIST="1"
npm.cmd run test:browser
```

`npm run build` يحتاج اتصالًا بالإنترنت وقت البناء فقط لتحضير نسخة Supabase المثبتة إلى `dist/supabase-vendor.js`. ملف المصدر `index.html` يبقي رابط CDN المثبت لتسهيل المعاينة المباشرة غير المبنية، لكن build يستبدله بملف محلي ويزيل jsDelivr من CSP الإنتاجي؛ لذلك الزيارة المنشورة لا تعتمد على CDN لـSupabase وقت التشغيل.

## هيكل الملفات الرئيسي

- `app.js` — واجهة المنتجات الأساسية.
- `quote-list.js` — قائمة طلب عرض السعر المحلية، الكميات، نافذة الطلب ورسالة واتساب المجمعة.
- `analytics.js` — GA4.
- GA4 Measurement ID مضبوط حاليًا في `config.js`: `G-WQRZWGY367`. بعد النشر تحقّق من Realtime.
- `catalog-pdf-viewer.js` — عرض PDF داخل الموقع بتحميل كسول.
- `public-sync.js` — مزامنة البيانات العامة مع Supabase.
- `admin.js` — النواة والتنقل والمصادقة في لوحة المدير.
- `admin-*.js` — وحدات لوحة المدير، ومنها `admin-datasheet.js`.
- `style.css` — نقطة دخول CSS.
- `styles/` — وحدات CSS المصدرية.
- `supabase/UPGRADE_EXISTING_V110.sql` — تغييرات v106–v110 للقواعد الموجودة.
- `supabase/UPGRADE_EXISTING_V111.sql` — إضافة تحكم ظهور قائمة طلب عرض السعر.
- `supabase/migrations/` — سجل migrations التاريخي/القابل للتتبع.
- `legacy/` — ملفات الإصدارات القديمة للرجوع فقط؛ لا تستخدمها في نشر جديد.
- `scripts/build.mjs` — الفحص والبناء والتصغير وتوليد الإصدار وCSP وربط Supabase المحلي للإنتاج، ثم تشغيل مولّد صفحات SEO.
- `scripts/generate-static-pages.mjs` — جلب المنتجات/الأقسام الظاهرة من Supabase وتوليد `/p/` و`/c/` و`sitemap.xml`.
- `tests/static-pages.mjs` — اختبار مولّد الصفحات الثابتة ببيانات وهمية آمنة.
- `tests/` — اختبارات static وPlaywright.

## ملاحظات أمنية

- رابط `?admin=1` ليس سرًا؛ الحماية الحقيقية هي Supabase Auth + RLS.
- لا تضع `service_role` أو Turnstile Secret في ملفات الواجهة.
- سياسة الخصوصية موجودة في `privacy.html` ويجب مراجعتها قانونيًا حسب نشاط المنشأة.
- مكتبات PDF/Excel الخارجية مثبتة بإصدارات محددة وSRI حيث يدعم أسلوب التحميل ذلك.
- Supabase في **نسخة الإنتاج** يصبح أصلًا محليًا `supabase-vendor.js` بدل تحميله من CDN وقت زيارة المستخدم.

v111D تبني على v111C وتضيف تحكم المالك في إظهار/إخفاء قائمة طلب عرض السعر؛ v111C أضافت قائمة طلب عرض السعر متعددة المنتجات؛ v111B أضافت صفحات SEO الثابتة ومسارات المشاركة الجديدة؛ v110 قلّلت حجم الملفات المركزية ويواصل الانتقال التدريجي إلى وحدات منفصلة بدون إعادة كتابة خطرة للمشروع دفعة واحدة. يمكن لاحقًا نقل أقسام إضافية من `app.js` و`admin.js` إلى وحدات، لكن هذا الإصدار يركّز على الانقسامات الأقل مخاطرة مع الحفاظ على السلوك الحالي.
