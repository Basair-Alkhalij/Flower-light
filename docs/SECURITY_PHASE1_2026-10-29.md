# Flower Light — المرحلة الأولى من خطة الأمان (29 أكتوبر 2026)

## الحالة
- تمت مراجعة مشروع Supabase الإنتاجي باستخدام استعلامات قراءة فقط وSecurity Advisor؛ لم تُعدّل بيانات المستخدمين أو الجداول أو صلاحيات RLS.
- قاعدة البيانات: حماية RLS موجودة على الجداول العامة والخاصة. لا يمتلك `anon` أو `authenticated` صلاحية `INSERT` المباشرة على `public.customer_leads`.
- وظيفة `manage-admin-account` منشورة ونشطة مع `verify_jwt=true`. وظيفة `submit-customer-lead` نشطة مع `verify_jwt=false` عن قصد لاستقبال الزوار بعد التحقق من Turnstile.
- متغير `pwa_install_enabled` ليس من إعدادات الأمان الحساسة؛ لا داعي لتغييره ضمن هذه المرحلة.

## إجراءات أمان واجبة (لا تُنفذ تلقائيًا)
1. **MFA لحسابات إدارة الموقع:** أظهر فحص `auth.mfa_factors` بالقراءة فقط أن حساب `owner` (واحد) وحساب `subadmin` (واحد) لا يملكان عامل MFA بحالة `verified`. يجب تسجيل العامل لكل حساب وتجربة تسجيل الدخول والاستعادة قبل فرض متطلبات MFA؛ تعطيل/فرض MFA على مستوى المنتج وحده لا يكفي. لا تحفظ رموز الاسترداد في GitHub.
2. **Leaked Password Protection:** يسجل Supabase Security Advisor تحذير `auth_leaked_password_protection`. فعّلها من **Authentication → Providers → Email / Password security** إذا كانت خطة المشروع تدعم ذلك (حسب [الوثائق](https://supabase.com/docs/guides/auth/password-security)، تتوفر على Pro وما فوق). راجع أيضًا طول كلمات المرور المسموح.
3. **SECURITY DEFINER:** يسجل Advisor 3 دوال عامة قابلة للتنفيذ من `anon` و22 تحذيرًا لدوال قابلة للتنفيذ من `authenticated`. اثنتان من الدوال العامة تعرضان معلومات منشأة/حسابات بنكية ظاهرة فقط، والثالثة `log_site_event` لتسجيل الإحصائيات. لا تسحب صلاحياتها بشكل أعمى؛ راجع شرط التفويض وحدود الإدخال والسجلات قبل التغيير، مع اختبارات سلبية بحساب غير مخول. راجع: https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable
4. **سياسات الوصول:** توجد جداول `customer_lead_rate_limits` و`quote_requests` مع RLS بلا سياسات. هذه جداول داخلية مقفلة؛ ليس من الصحيح إنشاء سياسة عامة فقط لإزالة التحذير.

## التغيير البرمجي الآمن
- التحقق من SHA-256 لنفس نسخة حزمة `@supabase/supabase-js@2.57.4` التي يجلبها البناء. **يرفض البناء** الملف البعيد أو الملف المحلي الاختباري إذا اختلفت بصمته عن البصمة المثبتة. تستمر بصمات مكتبات PDF كما كانت.
- تصحيح تعليق `config.js` القديم: عند تعطّل Turnstile تفشل عملية إرسال طلب العميل بأمان، ولا يوجد مسار `INSERT` مباشر بديل.

## خطة تحقق ما قبل الدمج
- نجاح اختبارات `npm run test:static` و`npm run build` و`npm run test:browser` على الفرع.
- تجربة رفض حزمة Supabase مختلفة باستخدام `FL_SUPABASE_VENDOR_FILE` في اختبار محلي/CI؛ يجب أن يفشل البناء قبل نشرها.
- عدم تغيير الأسعار أو صلاحيات الإنتاج أو بيانات العملاء.

## خارج النطاق حاليًا
- عدم تغيير إعدادات MFA أو كلمات المرور من قاعدة البيانات يدويًا.
- عدم تحديث Edge Function على الإنتاج قبل اختبار توافق نسخة GitHub وتفعيلها في مرحلة مستقلة.
- عدم العبث بسياسات `SECURITY DEFINER` أو إزالة فهارس لمجرد ظهور تحذير Advisor.
